# Tier 1 — 우리 held-out과 **지표 종류가 같은** 논문

> 보정에 쓰지 않은 **별도 관측**에서 3D 위치를 맞히고 독립 GT와 비교한다. 우리와 논리가 동일하다.

## ① C1. FusedBA (Sensors 2024) ★ 최우선

📄 https://www.mdpi.com/1424-8220/24/23/7416 · [데이터·프로젝트](https://koonyook.github.io/MCalib/)

**결과 — 독립 기록 3D 점 오차 2.14310 ± 0.01418 mm**

| 방법 | 독립 3D 오차 | 학습 재투영 |
|---|---:|---:|
| Anipose | 10.06 mm | — |
| BAp15 | 2.33 mm | **0.231 px** |
| **FusedBA** | **2.14 mm** | 0.260 px |
| MocapAssisted | 1.36 mm | — |

> 🔑 **이 표가 이 논문의 진짜 값어치다.** 학습 재투영이 **더 낮은** BAp15(0.231 px)가
> 독립 3D는 **더 나빴다**(2.33 vs 2.14). **"작은 px가 좋은 mm를 보장하지 않는다"**는
> 우리 주장의 **외부 근거**다.

**센서**

| | |
|---|---|
| 보정 대상 | **e-con See3CAM_24CUG ×7** — RGB 1920×1200 글로벌셔터 |
| GT 장비 | **Qualisys Arqus A12 ×10 + Miqus M3 ×6** (200 Hz) |
| 로봇 | ❌ 없음 |

**RealSense 대비**

| | |
|---|---|
| 가격 (카메라) | **≈ 1배** — 대당 20~30만 원, 7대 총 ≈ 200만 원 |
| 가격 (GT 장비) | **30배 이상/대** — 대당 1천만 원대로 알려짐, 억대 시스템 |
| 성능 | **화소 2.5배**(2.3 MP vs 0.92 MP). **글로벌셔터**(우리 color는 롤링셔터). 깊이 없음 |

**왜 추천 —** 카메라 가격대가 우리와 같은데 2.14 mm가 나왔다. **평가 설계**("보정 → 별도 기록 → 독립 GT 대비 3D 오차")를 그대로 가져오면 우리 외부 GT 평가를 선행연구로 방어할 수 있다.
⚠️ 볼륨이 수 m라 탁상(0.43~0.89 m)인 우리와 **거리 조건이 다르다.** 우리 거리에서는 바닥이 더 낮아야 정상이다.

## ② C6. Ohshima (Sensors 2026)

📄 https://www.mdpi.com/1424-8220/26/3/777

**결과 — 카메라 대수별 3D 재구성 오차** (45개 고정점, 20회 반복)

| 카메라 수 | 오차 |
|---:|---:|
| 10대 | **1.445 ± 0.833 mm** |
| 5대 | 2.113 ± 0.662 mm |
| 3대 | 5.121 ± 2.753 mm |

**센서** — 모델 `미확인`, 비동기 카메라 3/5/10대. 로봇 ❌
**RealSense 대비** — `미확인`

**왜 추천 —** **카메라 대수와 정확도의 관계를 실측으로 보여주는 드문 표다.** 우리 고정 3대 구성의 한계를 논할 때 직접 인용 가능.
⚠️ gold standard가 영상 기반이라 독립 계측 GT가 아니다. **3대에서는 보간이 오히려 나빴다**는 점도 같이 인용해야 공정하다.

# Tier 2 — **타깃(큐브)이 우리와 겹치는** 논문

## ③ N1. Marker-Based Multi-Camera Calibration (arXiv 2025) ★ 신규 발굴

📄 https://arxiv.org/abs/2505.02539

**결과 —** angular error 0.83° → **0.41°** (50 % 감소). Tech4Diet에서 인체 모델 300+ 재구성에 실사용.
⚠️ **"positional error 0.0012 mm"는 자기 일관성 잔차로 의심된다. 원문 표 확인 전 인용 금지.**

**센서 — Intel RealSense RGB-D 12대** (3열 배치). 로봇 ❌. 타깃은 **녹색 큐브 마커**(직교성을 제약으로 사용)

**RealSense 대비**

| | |
|---|---|
| 가격 | **1배 — 완전히 같은 센서.** 단 12대라 총액은 우리(4대)의 **3배** ≈ 360만 원 |
| 성능 | **동일.** 차이는 오직 **대수** |

**왜 추천 —** **가격도 성능도 타깃도 우리와 같은 유일한 논문.** "대수를 12대로 늘리면 뭐가 달라지나"를 볼 수 있는 유일한 창이다.

## ④ C5. Imperfect 3-D Targets (IEEE TIM 2026)

📄 https://ieeexplore.ieee.org/document/11408373/

**결과 —** ⚠️ **초록만 확인. 정량 `미확인`**
**센서 —** 카메라 3대, 고해상도 생체영상. 모델 `미확인`. 로봇 ❌

**왜 추천 —** **"3D 타깃 자체에 제작 오차가 있다"**고 보고 target geometry와 calibration을 동시에 개선한다.
우리 큐브의 면 간 위치·각도·출력 치수 오차와 **정확히 같은 문제 설정**이다. 수치는 못 쓰지만 **문제 제기의 인용처**로 최적.

# Tier 3 — 로봇 포함, 0~5 mm 보고

> **전부 우리 held-out과 다른 것을 잰다.** 인용할 때 "무엇을 재는지"를 반드시 함께 적을 것.

## ⑤ R8. EasyHeC++ (IROS 2024) — 종류가 가장 가까움

📄 https://arxiv.org/html/2410.09293 · [프로젝트](https://ootts.github.io/easyhec_plus/)

**결과 — 로봇이 실제로 마커 코너를 짚은 거리**

| 설정 | 결과 | 비교군 |
|---|---:|---|
| eye-to-hand targeting | **3.0 mm** | EasyHeC 4.0 / EasyHeC(SAM) 3.0 |
| eye-in-hand targeting (10 trials) | **3.1 mm** | Zhang 13.5 / Valassakis 43.0 |

**센서 — RealSense 1대** (삼각대 또는 EE 장착). 로봇 xArm7 / Baxter. 학습 ✅ (SAM·GroundedSAM·DKM)

**RealSense 대비 — 가격 1배 (같은 센서, 게다가 1대뿐 = 우리 4대의 1/4), 성능 동일**

**왜 추천 —** **센서로는 우리가 유리한데 3.0 mm가 나왔다.** 물리 targeting이라 우리 지표와 종류가 가장 가깝다.
⚠️ **baseline으로는 못 쓴다** — differentiable rendering에 로봇 CAD/메시가 필수인데 ZEUS엔 없다. **각주 인용용.**

## ⑥ R7. EasyHeC (RA-L 2023)

📄 https://ootts.github.io/easyhec/files/EasyHeC.pdf

**결과 —** xArm targeting **약 4 mm**. Baxter PCK3D@2 cm 0.15 / @5 cm 0.80
**센서 —** RealSense 1대(모델 `미확인`) + xArm7 / Baxter. 학습 ✅ (PointRend·PVNet, 각 10,000장)
**RealSense 대비 —** 가격·성능 **1배**

**왜 추천 —** R8의 선행 연구. 둘을 같이 인용해야 학습기반 계열의 발전을 정확히 서술할 수 있다.

## ⑦ R9. Calib3R (arXiv 2025 → v2 2026)

📄 https://arxiv.org/html/2509.08813v2

**결과 — hand-eye 변환의 translation 오차** (카메라 원점 계열, 물체 위치 아님)

| 데이터 | 오차 |
|---|---:|
| Franka Object | **4.15 mm / 0.63°** |
| UR Object | 6.36 mm |
| Franka Pattern | 11.27 mm |

> 단 마커 기반 Evangelista가 Franka Pattern **7.81 mm**로 더 정확하다. **markerless가 아직 마커를 못 이겼다.**

**센서 — Azure Kinect**(Franka 손목) / **RealSense D435 ×2**(UR5 EE). **전부 손목 장착.** 학습 ✅ (MASt3R/DUSt3R/VGGT)
**장수 —** 15~25 자세, **10장 미만도 동작**(최소 5)

**RealSense 대비**

| | |
|---|---|
| 가격 | Azure Kinect **≈ 1.5~2배** ($399, 단종). D435는 1배 |
| 성능 | Azure Kinect가 **깊이·화소 모두 우위** — 깊이 계통오차 11 mm + 0.1 % 미만, color 12 MP(약 13배 화소) |

## ⑧ R11. PlaneHEC (ICRA 2025)

📄 https://arxiv.org/html/2507.19851

**결과 —** 30 sample에서 **3.35 mm / 0.13°**
⚠️ **50회 재추출의 표준편차다. 정밀도이지 정확도가 아니다. 독립 GT 없음.**

**센서 — RealSense D435 1280×720 1대** + Flexiv Rizon 4. 학습 ❌ (RANSAC 평면검출)
**RealSense 대비 — 가격·성능 1배 (우리와 완전히 동일 센서·해상도)**

## ⑨ R3. Zhou, Multi Hand-Eye Graph (TIE 2024) — **구성이 유일하게 같음**

📄 https://arxiv.org/pdf/2305.02518

**결과 —** 폐루프 오차 **0.6274 / 0.6345 / 0.6938 mm**
⚠️ **참값을 못 재서 폐루프로 대신한 값이다. 작다고 정확한 게 아니다.** Wu 대비 일부 loop만 개선.

**센서 — Hikvision MV-CE060-10UC ×5** (6 MP RGB) = **손목 3 + 고정 2**. 로봇 UR5 ×2 + UR3

**RealSense 대비**

| | |
|---|---|
| 가격 | **≈ 1~1.3배** (대당 20~40만 원, 단종. 정확한 공개가 `미확인`) |
| 성능 | 화소 **면적 6.8배 / 선형 2.4배** (3072×2048 vs 1280×720). 깊이 없음 |

> 🔑 **고정캠과 손목캠을 한 최적화로 푸는 유일한 선행연구.** 우리 기여를 주장할 때 가장 성실하게 비교·인용해야 한다.
> 🔑 **비슷한 가격에 선형 해상도 2.4배** — 우리가 깊이를 안 쓰므로 **비용 대비 효과가 가장 큰 업그레이드 후보.**
> (단 우리가 1920×1080으로 올리면 격차는 **1.6배**로 줄어든다.)

# Tier 4 — 숫자가 아니라 **평가 방법**을 빌릴 곳

## ⑩ C8. AIRLS (Photonics 2024)

📄 https://www.mdpi.com/2304-6732/11/9/867

**결과 — 보정과 다른 검증 wand**로 5회씩 측정

| wand | 오차 |
|---|---:|
| 390 mm | **0.42 ± 0.09 mm** |
| 500 mm | **0.46 ± 0.13 mm** |

**센서 — OptiTrack FLEX13 ×4** (IR mocap, 1280×1024 @ 120 Hz, 약 2 m). 로봇 ❌. 약 1,000 frame

**RealSense 대비**

| | |
|---|---|
| 가격 | ✅ **대당 $1.5K (약 200만 원) = 6~7배.** 4대 + 소프트웨어 → 시스템 **10~20배** |
| 성능 | **3D 재구성 sub-mm.** 단 **반사 마커만 본다 — 일반 물체를 아예 못 본다** |

**왜 추천 —** "보정 데이터와 평가 데이터를 분리한다"는 원칙의 깔끔한 실물 사례.
⚠️ **두 마커 사이 거리**라서 두 점이 같이 밀리는 **공통 편향은 못 잡는다.** 우리 평가가 왜 거리가 아니라 위치여야 하는지의 대조군으로도 쓸 수 있다.

## ⑪ C9. Uncertainty Budget (Sensors 2023)

📄 https://www.mdpi.com/1424-8220/23/2/589

**결과 —** CMM 기준 LME **최대 0.030 mm, 평균 0.013 ± 0.008 mm**
**센서 —** 산업 카메라 2대 + **CMM**(좌표측정기). 로봇 ❌

**RealSense 대비 —** CMM은 **억대 = 300배 이상**. 성능은 **0.03 mm급으로 두세 자릿수 우위**(계측실 전용)

**왜 추천 —** **우리 외부 GT에도 오차가 있다.** GT 불확도를 어떻게 보고할지의 형식을 여기서 가져오면 "GT 대비 3 mm"라는 문장이 훨씬 방어된다.

## ⑫ D1. METRIC 데이터셋 (Information 2023)

📄 https://www.mdpi.com/2078-2489/14/6/314 · [데이터](https://zenodo.org/records/7976059)

**결과 —** 실물 RWHE 평균 translation (small D455): Shah 23.90 ± 6.99 mm / Evangelista 45.14 ± 16.06 mm. **10,000장 이상**
**센서 —** Kinect V2 / RealSense D455 / L515 각 4대. 보드를 EE에 부착(손목캠 없음)

**RealSense 대비**

| 센서 | 가격 | 성능 |
|---|---|---|
| Kinect V2 | **더 쌈** (단종·중고 10~20만 원) | 근거리 깊이는 좋으나 **표에서 D455보다 낫지 않음** |
| D455 | **≈ 1.5~2배** (리퍼 ✅ $320) | 깊이 4 m에서 2 %(D415는 2 m) → 원거리 우위. **color는 오히려 낮음(1280×800)** |
| L515 | ≈ 1배 ($349, 단종) | LiDAR라 실내 근거리 깊이가 깨끗. R2 표에서 최상위 행 다수 |

> 🔑 **D455로 바꾸면 color 해상도가 오히려 내려간다.** 우리 목적(코너 해상도)에는 다운그레이드다.

**왜 추천 —** **GT가 AprilTag + CAD + FK로 만들어졌다.** 우리 외부 GT가 왜 이보다 강한지를 **대비시켜 서술**하기 좋다.

## ⑬ R5. Uncertainty-Aware Hand–Eye (T-RO 2024)

📄 https://publikationen.bibliothek.kit.edu/1000167305

**결과 —** UR3e에서 RRMSE **0.193 px**, RAE **0.00073 mm²**
⚠️ **RAE는 mm가 아니라 mm²(평균 제곱 재구성 오차)다.** 0.00073을 mm로 읽으면 안 된다.
⚠️ 0.193 px는 **보정된 로봇 pose로 평가한 값**이라 raw FK를 고정한 우리 평가와 직접 같지 않다.

**센서 — IDS U3-3280SE** (2448×2048 = 5 MP) + **8 mm 렌즈 별도**. 로봇 UR3e. **25 자세**

**RealSense 대비**

| | |
|---|---|
| 가격 | **≈ 3~5배** (본체 70~130만 원 + 렌즈. 정확한 공개가 `미확인`) |
| 성능 | 화소 **면적 5.4배 / 선형 1.9배**. 산업 계측 등급 렌즈. 깊이 없음 |

> 🔑 **0.193 px는 이 센서 품질이 전제다.** 우리 px와 직접 비교하면 안 되는 이유.

**왜 추천 —** ① FK를 불확실하게 다루는 우리 soft anchor의 최신 필수 baseline. ② 단위 함정(mm²)의 교훈.

# 보너스 — 비교표 필수 행

## R2. Allegro, Multi-Camera Hand-Eye (RA-L 2024)

📄 https://arxiv.org/html/2406.11392 · [코드](https://github.com/davidea97/Multi-Camera-Hand-Eye-Calibration)

**결과 — GT translation** (카메라 **원점** 위치 오차)

| 데이터 | 오차 |
|---|---:|
| small / D455 | **13.21 mm** |
| small / L515 | 13.68 mm |
| large | 19~45 mm |

⚠️ **이건 카메라 원점 위치 오차이지 물체 위치 오차가 아니다.** 원문 식 (8)로 확인:
$e_t^{GT}=\frac{1}{N}\sum\lVert t-\hat{t}\rVert_2$ — 카메라별 오차를 평균한 값.
회전은 0.07°로 매우 작은데 이동만 13 mm인 것은 오차가 **광축 방향**에 몰려 있다는 신호다.

**센서 —** Kinect V2 / D455 / L515 ×4 (전부 고정). 산업셀은 ABB 4대 · KUKA 3대
**장수 —** 산업 실험은 **10장 미만, 15장**으로 보정

**왜 추천 —** **"결합(joint optimization)"을 가진 유일한 최근접 경쟁자**이고, RealSense+로봇+멀티캠을 다 만족하는 유일한 논문. **코드가 공개돼 우리 데이터로 직접 돌릴 수 있는 baseline.**

# 한눈에 — 가격 대비 성능

| 배수 | 논문 | 센서 | 성능 요지 |
|---:|---|---|---|
| **1배** | **N1, R8, R7, R11** | **RealSense 그대로** | 우리와 완전 동일 조건 |
| ~1배 | C1 | e-con See3CAM | 화소 선형 1.5배 + 글로벌셔터, 깊이 없음 |
| **1~1.3배** | **R3** | **Hikvision 6 MP** | **화소 선형 2.4배** ← 최고 가성비 |
| 1.5~2배 | R9, D1 | Azure Kinect / D455 | 깊이 개선. **color는 그대로거나 낮음** |
| **3~5배** | **R5** | **IDS 5 MP** | 화소 선형 1.9배 + 계측 등급 렌즈 |
| 6~7배/대 | C8 | OptiTrack Flex13 | sub-mm. **마커만 봄** |
| 30배+ | C1의 GT | Qualisys | GT 전용 |
| 300배+ | C9 | CMM | 0.03 mm급. **다른 세계** |

## 여기서 나오는 결론 3가지

1. **0~5 mm를 보고한 논문 중 절반이 우리와 같은 RealSense를 쓴다**(N1·R8·R7·R11).
   → **센서가 우리 발목을 잡는다는 증거가 없다.**
2. **업그레이드는 R3 노선이다** — 비슷한 값에 선형 2.4배.
   D455(R9·D1 노선)는 깊이만 오르고 **color는 오히려 낮아** 우리에겐 무의미하다.
   그리고 **우리가 먼저 1920×1080으로 올리면 공짜로 선형 1.5배**를 얻고, R3 격차는 1.6배로 줄어든다.
3. **sub-mm 논문들은 전부 6배~300배 장비다.** 같은 표에 넣으려면 **센서 열을 반드시 함께** 넣어야 한다.
